# 从原始诉求到少往返的校园复刻流程

2026-10-30 按人类发言与 Agent 反馈、产物分别复查后整理。此页是匿名归纳；原始会话、私人日志和校园素材不随仓库公开。

## 最初就确认了什么

任务从特定学校和校区开始，要求 Agent 找官方地图确定整体分布，逐栋检索足够细的实景照片，再利用造世界的生成能力复刻。学院楼、宿舍、教学楼、校门和体育场地都在范围内；完整基础设施优先，玩法放后面。

Agent 在早期已经提出并获得确认：官方地图 → 逐栋清单 → 多角度照片 → 身份筛选 → 统一比例、朝向与地基 → 技术样板 → 分区持续制作。用户并未要求先亲自收齐图片，也没有把整个校园改为一栋楼的演示任务。

## 人类要求、反馈与结果分别看

| 人类已确认的要求 | Agent 的反馈或实际偏差 | 新 Skill 固定的用法 |
|---|---|---|
| 依官方地图复刻整个校园 | 已找到地图，但局部路线、入口和细节长期占据工作，后来才系统核出缺楼 | 地图全集是任务选择器；每批回到全图缺项，不按容易展示的局部选任务 |
| 每栋建筑先找真实照片 | 有照片库和生成记录，但部分楼只有外壳、入口或局部立面 | Agent 自行检索，核身份和角度；占位/局部与整栋、照片精修分开 |
| 补齐所有建筑与场地并接地 | 用户后来重复指出学院楼未完整、悬空和篮球场遗漏 | 建筑、路、门、球场等都入清单；全周接地和完整楼体是独立门槛 |
| 完成一批就继续下一批 | 对话多次用于催继续或恢复已用过的连接 | 保存任务状态和恢复方法，普通步骤持续执行，不逐栋重新请求确认 |
| 先完整校园再加玩法 | 跑步等单项反复回归，基础缺项仍未解决 | 单项必要测试通过后退出；新修改/失败才重测；基础阶段锁定优先级 |
| 想看哪些做到、哪些不足、哪些未做 | 资产包数、局部成功和模型存在容易被理解成整栋已完成 | 地图真实名称对应照片、模型、场景和证据，按全图三类状态报告 |

## 实际有效的闭环

逐栋：**检索核实资料 → 参考图组 → 生成/搭建 → 对照照片 → 调整尺寸和位置 → 接地/通行 → 原生保存 → 更新清单 → 下一栋。**

同时维护运行状态：实际工程、保存版本、工具恢复办法、在途任务、预算余量与下一项。未知结果先查，不因超时重新导入一份。某栋资料不足时换来源或转下一栋，最终集中处理仍需用户决定的冲突。

样板校准是这条长链的内部技术关卡，只证明当前生成/导入方法可用。它不缩小总范围，不意味着每栋都要再等用户批准。

## 哪些信息应在开头收，哪些由 Agent 补

| 用户给出或确认 | Agent 主动完成 |
|---|---|
| 学校/校区、整体目标、不可改区域 | 官方地图定位、全图盘点、与现有场景差异 |
| 当前工程及允许的资源边界 | 逐楼检索照片、身份/角度核对和缺口清单 |
| 重要风格与真实审美取舍 | 施工规格、比例朝向、批量生成/落位、保存和验收 |
| 必需登录或不可自行判断的冲突 | 普通故障定位、查重、续接和下一栋推进 |

## 后期工具与美化属于哪一层

编辑器指南在开工前已阅读，在对象前提与故障诊断中起过作用；不能从“读了”推断每次操作都完整遵循。社区 MCP 是后续工具升级，实际承担导入、变换、替换、回读与保存；原生生成、界面和实走仍各有作用。七处主题装饰是后期二创，不能把它们当作最初全校园复刻的范围。

这份 Skill 把上述实践和偏差转成下一次的执行规则，尚未证明一条提示能对所有校园复现相同质量。衡量是否减少对话，要同时看全图完成度、照片相似度、漏项、返工与需要人决定的次数，不能只数对话少了多少。
