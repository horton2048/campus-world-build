# 跨上下文的校园施工循环

本页用于整校这种长程任务。默认和主流程一起读；涉及某栋时再读它的详情，不把整段聊天、全部图片和工具日志重新塞进上下文。此协议负责保持方向、保存进度和恢复；模型生成与编辑仍使用当前真实可用的工具。

## 一句话进入，先形成可保存的任务约定

用户可以只说：

> 使用 $campus-world-build，复刻【学校】【校区】。

已有会话中的工程、目标与授权直接继承。默认是官方地图范围内的完整室外校园，逐栋主动查实景，先基础后美化；不要求用户再抄完整流程。先做不消耗生成额度的资料工作。校区有歧义、没有编辑权限、现有工程选择或收费边界必须由本人决定时，合并成一组明确问题；不要为了“一句话”擅自充值、选错校园或隐藏必要登录。

把任务约定持久化：学校与校区、原始范围/排除区、地图来源、照片与完整楼体门槛、阶段顺序、工程身份、权限、预算、停止条件和用户后续变更。摘要不得自行缩小范围；修改约定要能对应用户的新指示。

## 什么保存在哪里

使用 [检查点工具](checkpoint-tool.md) 保存运行记录；只有确实不能运行 Python 时，才采用下方等价文件协议，并报告失去了哪些自动校验。

| 记录 | 必须留住的信息 | 恢复时怎么读 |
|---|---|---|
| 项目约定 | 学校/校区、范围、当前阶段、地图全集是否复核、工程身份、用户授权、资源边界、最后原生保存和回读证据 | 每次进入先读短摘要，再按需读取完整项目 |
| 每个地图项 | 稳定ID、真实名称/类别、地图和照片来源、身份依据、缺角度、规格、源文件/SHA、资产与实例映射、检查证据、下一动作 | 只读本轮要操作的对象；全图审计分页取索引 |
| 每次外部写入或耗额提交 | 不变的操作ID/去重指纹、目标工程与对象、输入快照、预期变化、方法、尝试次数、提交前意图、真实句柄、最后观察、结果/缺口 | 所有未确认终态的操作优先；不能只看“下一步”文字 |
| 历史与证据 | 失败签名、原方法、排除过什么、已核实替代路径，截图/源文件/原生版本索引 | 按对象或失败签名查片段，不整份读入 |

图片、GLB、原生备份和长工具回包放项目文件，记录引用、时间与内容哈希；不把二进制或大段日志写进恢复卡。短卡是派生索引，不能覆盖权威记录。没有上下文百分比也能工作：**每次外部写入前后、每栋/每批结束、已知交接或停止前都写检查点**，不要等窗口快满才补记。

短卡整体默认不超过16 KiB；窗口小或容量未知时，先 `resume --limit 3 --max-bytes 4096` 再读，逐项详情按需加载。按 `hasMore/nextPage` 查相同集合的余下作业；期间发生写入或 `eventSeq` 变化就从首页重查，不能把旧 offset 用到变化后的集合。不要因摘要只留几个ID而误以为其他任务不存在。本轮只保留约定、未知作业和当前少量对象；长历史、旧图与已通过的批次留在文件索引里，不在每次续做中重新灌入。按故障类型读取相关参考章节，不同时加载全部失败案例和完整工具回包。

首次开工在**任务工程根目录**留下小型 `CAMPUS_TASK.md` 入口：学校/校区、记录目录、Skill位置、恢复命令和工程身份核对方式；不要只把目录记在聊天里。同项目已有入口就追加/沿用，不覆盖其他校园。新会话只知道项目时，先找这个入口，再读恢复卡；没有入口再在当前任务项目内定位数据库/恢复卡，不扫描整台电脑、不任选同名校园。此入口只是定位器，实际状态仍以权威记录和编辑器查询为准。

用户说“继续”却没找到记录时，不当作空白新建：先核现有编辑器工程与可访问的任务资料，尝试恢复地图项/资产映射；仍不能确定原工程或记录位置时集中问这一处必要信息。不要另造第二份世界，再把它说成无缝续做。

等价文件协议：`project.json` 保存小型任务约定，`items/<id>.json` 和 `jobs/<id>.json` 分项保存，`events.jsonl` 只追加，`RESUME.md` 为可重建摘要。写前读最新版本和校验值，临时文件完整写入后原子替换；同场景单一写者。全部日志不作为恢复必读材料。不具备事务时，先以追加事件记录意图及结果，再重建快照；崩溃后不能假定多个文件都已更新。

## 每轮按同一规则选任务

1. **先恢复真实状态。**读短卡，核学校/工程身份，读取未终态作业详情，向原工具查询真实句柄和对应场景/资产。再读本轮所需的逐栋资料。记录与真实场景不符时，保留冲突，先解释差异再修改；不能用旧卡覆盖新场景。
2. **优先处理未知写入。**查证之前是否已经生成、导入、摆放或保存，避免新上下文再做一份。只要工程级写入结果不明，就暂缓有冲突的场景写入；仍可查下一栋照片。
3. **回到全图基础缺项。**按未做建筑/场地、缺完整楼体、位置/悬空、照片精修的顺序，选依赖已满足且资源允许的一项；基础未覆盖时不能因已有玩法容易展示而改做玩法。
4. **执行一个有界动作并验结果。**读当前输入 → 保存意图 → 调真实工具 → 保存回包/句柄 → 查回/看图 → 记录证据与未过项。异步生成等待期间可查下一栋资料；同一场景只有一位写入负责人。
5. **更新后继续。**记录全图计数变化和下一项，立刻选下一可执行工作，不因一栋完成结束为“等你说继续”。某项受阻就保留缺口转可做项；所有项确实受阻时，集中给出本人需要完成的动作及可恢复状态，不做空循环。

开始每轮都检查预算与连接；队列是从当前全图状态、依赖和在途任务推导的，不盲信上次写下的顺序。

## 异步操作：观察失败不等于任务失败

`job` 记录的是生成等耗额提交或导入、入场、替换、保存等外部写入。**查询、轮询、读场景和看图不为同一目标另建 job**，把观察写回原作业的 `observation` 或逐项证据；否则会与尚未解决的作业查重冲突。纯查询可并行，场景写入仍须顺序。终态作业不可改写旧事实，后续新观察追加到项目/逐项记录中。

| 状态 | 能做什么 | 不能做什么 |
|---|---|---|
| `prepared` | 提交前意图已保存；若发生中断，先按指纹/源哈希/目标去查是否发出过 | 没句柄就推断“没调用过”，直接重做 |
| `submitted` / `running` | 用同一真实句柄继续观察；有独立资料任务时先研究 | 观察超时就另起生成或导入 |
| `unknown` | 保留原意图/句柄，查任务、源产物、个人资产和场景实例；必要时用原生界面 | 标成完成，或仅因连接断开标成失败 |
| `succeeded` | 该操作被权威结果确认；继续做视觉、接地、保存等独立验收 | 把一个导入成功当作整栋完成 |
| `failed` / `cancelled` | 有权威终止证据并查清副作用后，可准备新的尝试ID | 重开旧终态，丢失曾经失败和已花额度 |

查询不到句柄只是观察结果。先确认是否查了正确账号、工程、分页和方法，并查看资产/场景是否已发生变化。若接口无法证明“确未提交/已终止且无副作用”，保持 `unknown`，换不冲突的工作；确需本人处理时明确给出待查对象，不能用假失败消除重复风险。

等待只对**当下确认存活**的任务/进程成立。台账里写了 running，不证明任务还活着；不能用时间流逝或重复汇报冒充进展。轮询遵循工具的建议间隔与宿主允许时长，每次更新最后观察证据；响应不确定就查询同一任务，不重新提交。长时间无变化时可继续资料研究，不能凭观察超时认定任务终止。

## 让失败次数穿过压缩窗口

按“对象＋方法＋输入快照＋错误签名”保存尝试次数及最后新证据，而非只记在聊天里。同一输入与同一方法连续两次失败、没有新增证据时停止盲试：查前提、减小批量、换当前受支持的方法，或先做其他项。成功路径详见 [真实失败处方](case-lessons.md)。

新方法需写明改变了什么和成功要看到什么。上次已通过的局部路线，无相关修改、无新失败、无缺失证据时不重跑。缺图项先换可靠来源和关键词；暂时不能辨认的保留，不能用虚构照片依据提高覆盖率。

同一失败不能因为换会话而重置次数。连续几轮既没改变产物/清单、没取得新证据、也没观察到真实任务变化，就停止该路径重新选项；若依赖都不可解决，报告受阻。不要为保持“运行”反复读相同文件或重做已经通过的演示。

## 预算、保存与真正结束

- 记录可花额度、已花与在途预留；余额未知时不当作无限。新付费任务在现有授权内才发起，未授权的充值/重置卡不自动使用。已耗尽时继续可做的查图、规格和静态检查，全部受限再停。
- 积分、GLB文件/面数、场景原生容量、实例数及工具截断是不同限制；按当前实测分别记录，不复用历史上限作通用常量。
- 原生保存的任务接受、实际保存完成、clean状态和回读确认分开。保存前保留源快照；部分保存失败或磁盘写入失败就停止下一次外部变更，先修复可恢复记录，不空口宣布已保存。
- 队列空了、会话结束、预算耗尽、所有项写了状态、某条路线通过，都不等于全校园完成。完成审计重新比较官方地图全集和场景，确认没有未盘点区域；逐项核地图/照片身份、整栋/完整场地、方向尺寸、接地通行、原生保存回读及用户约定的运行项。`not-applicable` 必须给原因；`unknown`、缺证据、待修正、未做或受阻都不能算达标。
- 用户明确变更范围时，保存其决定的依据，更新当前范围和地图项成员状态；被排除的旧项保留历史而不计本次覆盖。Agent 不能为了过验收自行排除难项；旧项仍有未知写入时先查清，不能借排除跳过有副作用的在途任务。
- 记录三类对话：开始约定、必要本人决策、用户纠偏/催促。后两类不能通过隐瞒缺口来“降低”。评价是否可复用，要同时看全图质量、漏项、返工、费用和用户纠偏次数。

## 宿主停止时怎样交接

Skill 本身不是后台进程，不能使已停止的 Agent 自动醒来。在同一运行轮次内持续推进；需要压缩/切换上下文时，用已保存状态接着做。若宿主支持且用户已经授权长程续跑，可交给现成机制；没有授权就不新建定时任务。

不可避免停止前更新权威检查点和短卡，写明：最后确认到哪一步、哪些写入仍未知、下一条真实查询/动作、恢复入口和真实待本人事项。恢复用户只需说“继续复刻【学校】【校区】”，不必重讲建筑照片、比例和失败历史。不能把“可恢复”说成“宿主停止后仍在施工”。
