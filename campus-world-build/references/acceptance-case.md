# 小案例验收：一栋建筑与入口路段

选用户已经确认身份的建筑，使用官方地图与至少可核实的主要外观照片。只操作独立 TEST 项目，保留正式工程。

1. 记录地图项与照片身份、用户确认、尺寸估计和入口方向；scope 明确为这一栋和路段。
2. 初始化检查点，写未完成建筑项和施工意图。恢复时读同一数据库，不重新 init。
3. MCP 路径：复用或导入真实模型，保存真实资产/实例ID，读取原生尺寸与支点后校准摆放。若需生成，先读 `generate capabilities`，经MCP→CLI `generate image/model/wait` 查询真实终态。电脑操作路径：按 [电脑操作](computer-use.md) 在界面完成支持的动作，记录可见标识、属性和截图；无法读取的ID、支点或尺寸明确标记未验证。
4. 实际对照照片、测量接地并正常走入口路段，保存、完全退出、冷开回读及截图；各自保留回执。
5. 从检查点恢复同一实例，确认不会重复导入和创建；由Agent实际查看照片/场景对照，自主验收并记录依据；展示结果供用户体验和反馈，不能等待用户代做技术检查。

软件层另验：旧修订号更新被拒绝、未知作业同指纹/同目标重发被拒绝、占位楼不得记成完成、恢复卡指到原作业。软件层可以用明确命名的本地记录示例，不把示例 evidence 字符串当真实生产证据。

最终结果分列：记录工具、实际入口施工、校园外观和玩法各自的证据与结果。前一项成功不替代后一项；依赖不足保留准确受阻阶段。
