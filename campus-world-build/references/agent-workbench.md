# 以 Agent 为唯一创作工作台

首次接入、换机器/工程或能力变化时读本页。用户通过 Agent 提要求、看图和改作品，造世界仍是实际制作与运行环境。MCP 与受支持的界面自动化都可由 Agent 操作；“不碰编辑器”指用户不用手工建场景，不等于无需账号权限，也不意味着 Skill 自带全部工具。

## Agent 接手开工准备

1. **接收学校和目标。**沿用已知学校、校区、工程、保留区和资源边界。地图与逐楼照片由 Agent 主动找；用户现有资料优先利用。
2. **实际读操作指南。**主动定位当前官方入口，读取本轮生成、导入、对象前提、保存及验收相关章节；记录来源和适用版本。用户给过指南时先读它，不再让用户抄教程。受权限限制读不到时，尝试已有获权资料；确需本人授权才集中说明。未读章节不能声称已掌握，界面变化要重新核实。[指南与 MCP](guide-and-mcp.md) 保存历史有效经验及来源。
3. **发现执行能力并连接正确工程。**先核能否读写文件、访问资料与看图、运行所需辅助工具，再读取编辑器工具目录和 schema，核账号、工程、已有实例、在途任务和保存状态。已有获权连接直接复用；新安装、启用额外权限或费用按当前任务授权处理。Agent 执行能执行的配置，不把终端命令和手工编辑器教程甩给零基础用户。
4. **走通代表性小样。**复用已有同版本证据，或在合适的测试范围完成生成/复用、导入、落位、读回、看图、保存和必要运行。小样是内部验证，随后继续全校园；不能把通过一栋改写成整校已自动完成。

只需保存一张动作覆盖表：本轮要做的动作、实际可调用入口、前提、当前验证证据、缺口。它用于指导 Agent，不要求用户读懂 MCP 或接口名称。具体工具路由见 [当前工具与前置条件](tool-routing.md)。

| 当前状态 | Agent 接下来做什么 | 对用户怎么说 |
|---|---|---|
| 已有可用工具链 | 自行读手册、制作和验收；接口缺项用获权 UI 自动化补齐 | 告知当前目标和下一份可看结果，不逐栋等“继续” |
| 需要本人身份动作 | 把申请、登录、验证码等不能代办的动作集中列出；继续独立的资料工作 | 只给当前真正必要的步骤与完成标志，不要求手工建模、导入或摆楼 |
| 某生成/编辑入口未覆盖 | 核当前工具与受支持 UI 自动化，验证可用路线；保留未解决状态 | 说清这一步尚未接通，资料准备到了哪里；不暗示已经生成或让用户按教程代做 |
| 只有文件工具，不能访问资料或看图 | 核已有资料，记录用户目标与能力缺项；能够可靠处理的本地文本先整理 | 尚不能主动查证校园、找图或完成视觉验收；不把“有文件工具”说成研究能力已具备 |
| 只有文字对话、不能读文件或执行工具 | 明确当前环境不具备实际自动制作能力，列出最低缺项 | Skill 不是聊天文本就能直接生成世界；用户需在有文件与操作能力的 Agent 环境继续 |

普通可逆的已授权制作不再申请逐步批准。本人登录/创作权申请与“用户亲自操作编辑器制作”分开，不能为了绝对零操作冒用身份或掩盖缺能力。用户主动选择手工环节时尊重选择，并如实记录由谁完成。

## 开工时给出可兑现的预期

先按当前证据描述效果层级：

- **资料与规划就绪：**正确校区、全图清单、参考照片和制作规格；这还不是可体验世界。
- **首批可看：**有照片依据的代表性建筑与真实场景截图，能判断制作方法和风格；这还不是完整校园。
- **基础校园：**全图建筑、校门、道路及场地有完整对应，位置方向和接地通行通过；照片精修另计。
- **精修/定制：**约定的建筑特征、风格和玩法完成各自验收；手机、多人或性能只在实测后报告通过。

用户可只复刻明确的局部。若约定整校，上述阶段只是进度，不允许 Agent 自行缩小交付范围。

## 时间预估由实测更新

不从一句话提示、离线脚本测试速度或历史制作的首尾日期推算整校工期。当前仓库没有任意新校园的完整工期基准；没有本轮数据时写“待首批校准”，并说明接下来测哪一段，不写虚假的分钟数。

可以为新手建议安排一次目标沟通、首轮可运行窗口和后续多轮检查时间；这是方便计划的时间盒，必须与实测预计明确分开，不能把“预留半天”说成“半天保证出首批”，或把“按多天迭代安排”说成“几天必定整校完成”。

将时间分开记录，避免让用户误以为需要全程盯着：

| 时间 | 怎么估 | 怎么更新 |
|---|---|---|
| 本人投入 | 提供学校/目标、完成必要身份动作、看关键结果并反馈所需的主动操作时间 | 用户尚未完成的登录/审批等待不计作 Agent 施工，也不承诺平台审批时限 |
| Agent 工作 | 地图查证、照片核对、实际制作与验收的有效处理时间 | 在首批中记录每类对象的步骤起止、数量与返工；区分建筑和道路/场地，不拿一栋套全校 |
| 外部等待 | 已提交生成排队、素材下载、平台处理等可观察的等待 | 优先采用服务实际排队/任务信息；等待可与资料检索重叠，不能机械相加 |
| 日历跨度 | 连接、机器运行、队列、依赖和本人回复共同决定的总跨度 | 分别给乐观/常见/受阻情形及依据；宿主停机的时段不伪装成持续工作 |

每个代表性样本记录：对象类型、资料是否齐、Agent 有效用时、生成等待、返工次数、验收结果、消耗。样本不足时只估下一批；足够覆盖不同类型后，用剩余对象分类、实测区间和依赖关系给阶段区间，标明样本量与未计入部分。失败未过的样本仍需计入成本，不能只挑最快成功项。每批以实际进展修正预计，缺图/连接变化/新玩法都可能改变工期。

对新手只展示一小段结论，例如：“首批能看到教学楼和校门的场景图。你先完成一次账号登录，之后主要在这里看图提意见。整校预计在首批校准后更新；当前仍缺生成入口验证。”示例不代表实际项目已经具备这些条件。技术统计留在项目记录，不灌进用户的每条进度消息。
