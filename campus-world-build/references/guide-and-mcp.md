# 操作指南、MCP 与 Agent 实际怎样配合

依据 2026-10-10 至 10-26 的校园记录，2026-10-30 重审。历史阅读、实际调用和最终效果分开说明；链接保留来源，不保证现行菜单、权限、数值与历史相同。

## 先给结论：两者都用上了，但没有覆盖全部执行

官方指南确实被阅读，帮助选择生成方式、理解地形等前提和区分保存/预览/发布。社区 MCP 先被读源码，后经 Mac 适配、小样验证，实际承担校园导入、落位、回读和保存。原生 AI 仍承担受支持的生成工作，真实 UI 补充接口未覆盖的入口和视角操作。

没有证据证明当时每一项操作都严格映射到某条指南并完成遵守审计。Agent 也曾在用户提醒后才查笔刷、官方交互模板，发生过忽略前提和反复局部测试。因此不能说“给了手册与 MCP，Agent 就全程照着自动做对”。Skill 是事后把有用路径和偏差整理成可执行约束。

## 1. 官方指南实际发挥的作用

10 月 10 日已读取官方导航的 **19 篇教程、FAQ 与社区案例文字**，形成逐篇文本和完整制作流程笔记。它提供三类有效知识：

| 文档知识 | 实际用途 | 仍需现场证明 |
|---|---|---|
| 静态模型、原生 Agent、组合资产/MIX 的区别 | 按建筑主体、生成模块和交互选择入口 | 当前版本是否提供该入口，产物与任务目标是否匹配 |
| 入库/落场、可见性/启用/碰撞、地形表面等前提 | 诊断“看得见不承托”“GLB 底板不能用该笔刷”等问题 | 对象类型、实际组件和动作结果 |
| 保存、本地运行、真机、多人、上传发布的阶段 | 避免把文件生成或静态截图当全部完成 | 每一阶段自己的保存、运行或远端证据 |

**明确有效的例子：**笔刷在 GLB 底板失败后，重新对照“在地形表面绘制”的前提，结合 UI 无地形提示，换成按真实绿地边界生成的三片合批短草层；这条替代路径完成归档、入库、落位、保存和局部穿行。指南帮助诊断和选路，不能把笔刷失败改写成成功。

**当时没做到的部分：**读取教程不等于观看全部内嵌视频；理解前提不等于每次动作都先检查。草坪批量化和官方交互模板都曾由用户再次提醒才查，必须作为下一轮前置检查，而非历史全程合规的证据。

## 2. 社区 MCP 从参考走到实际执行

来源：[WilderNoTrack/world-creator-mcp](https://github.com/WilderNoTrack/world-creator-mcp)。这是社区适配器，不是官方 MCP，也不是本 Skill 自带的安装包；本 Skill 没有复制它的实现。

| 历史阶段 | 实际做了什么 | 能证明什么 |
|---|---|---|
| 10 月 15 日首次收到链接 | 读仓库、目录和关键源码，比较方法，尚未安装连接 | 此阶段只能说参考了设计 |
| 当天获得安装/独立测试授权后 | 调整 Mac 启动与安装路径、子进程环境传递，限定写入测试项目 | 是经过本地适配的版本，不保证上游原版在任意 Mac 开箱即用 |
| 小样实测 | 53 项隔离测试、33 步核心实机链，包括导入、实例、变换回读、受支持组件、原生保存与重开 | 核心编辑链当时可用；发现 56 个工具不等于 56 项全验收 |
| 10 月 16 日后获权接入校园 | 读场景、导入、创建实例、落位、改受支持组件、回读和保存 | MCP 确实参与校园制作，不是只读过介绍 |
| 10 月 26 日七处美化与文字修正 | 实际导入、入场、变换、读回、替换实例和原生保存，有静态近景对应 | 精确部署与保存的作用可证明，生成和全运行不能全部归因于 MCP |

未覆盖/未证明：所有 PCG 云生成、发布、全部素材/对象类型、所有 Lua 调试功能，以及复杂建筑与手机/多人全面验收。历史能力发现也没有找到通用资产 AI Agent 的可用启动/续做入口；地图 PCG 入口不能替代资产生成入口。部分原生 Agent 提交、相机与实际体验依赖真实 UI。

某些结构化动作当时通过既有本地适配器 CLI 完成，并非当轮目录全部直接暴露。新项目必须发现当前可调用接口、读 schema 和验证连接，不能凭旧工具名字直接构造调用，也不能把历史可写工程授权带给其他用户。

## 3. 下一次的一句话启动，内部应展开成什么

用户只需给出可辨认的学校/校区和目标，Agent 自行处理资料与执行顺序。已提供的手册、地图、照片和可用连接优先复用，不重复索取。

1. **先恢复或建任务合同。**锁学校/校区、完整范围与验收、已有授权和资源边界；已有场景和任务先回读。官方资料不明确时继续检索，不默认让用户逐栋给图。
2. **按当前动作读相关规则。**从官方导航找本轮有关的生成/导入、对象前提、保存与验收章节；已有笔记有版本依据则复用，不每轮重读全部教程。新增功能或环境变化再补读。
3. **把规则对到真实入口。**发现当前工具与 UI，核能力、schema、对象类型和工程身份。已有获权连接直接使用；新安装/连接/权限变化按当次授权处理，不静默安装陌生服务。
4. **新路径小样验证。**先以一件同来源对象走通生成/复用、入库、入场、变换回读、保存/重开与实际画面。既有验证证据在环境未变时沿用。通过后自动返回全图队列，不缩成只做小样。
5. **持续闭环并留检查点。**结构化编辑优先；未覆盖时用受支持 UI。同一场景单写入；生成等待可做下一栋研究。每栋更新清单、产物/实例/保存版本和下一项；恢复时先查真实任务和场景，不能凭旧摘要重发。

这些是 Skill 的执行要求，不表示 Skill 自身会提供账号、权限、工具连接或宿主自动唤醒能力。

## 4. 用小记录证明 Agent 真的遵守了

不用把整本手册塞进每轮上下文。对当前动作保留一条可查记录，使用工作台账中的规则检查字段或同等结构：

```json
{
  "rule": "草层笔刷的承载对象前提",
  "source": "当前官方教程链接及读取日期/适用版本",
  "precondition": "需要原生地形；当前底板实际为GLB",
  "action": "停止不适用笔刷，改用按边界生成的合批草层",
  "actionEvidence": "本项目真实任务/资产/实例及操作记录的位置",
  "verification": "实际画面、保存和局部穿行；其他运行项待验"
}
```

此结构只是填写示例，不能复制为已发生的证据。至少区分：**文档描述了什么 → 当前前提是否满足 → 实际执行了什么 → 哪项结果已验/仍缺。**对无直接规则的操作写清所依据的当前 schema 和小样，不虚造官方规定。通过变换读回或文件检查，不自动补齐视觉/通行/保存项。

## 5. 四层各做各的事

| 层 | 负责 | 不替代 |
|---|---|---|
| 官方指南与示例 | 功能选择、前提、限制和验收依据 | 当前工具 schema、实际操作与效果 |
| 原生 AI / 编辑器 | 受支持的生成、编辑、保存和运行 | 完整校园研究、队列管理和全图验收 |
| MCP 与真实 UI | 结构化读写、变换回读；UI 补未覆盖入口和观察 | 新用户授权、全部生成能力和体验判断 |
| Agent + Skill | 把用户目标、地图照片、规则、工具、检查点组织成连续工作 | 账号权限、宿主续跑机制或尚未取得的验证证据 |

公开来源是背景与方法入口，部分官方文档可能需要访问权限。原始私有日志未在仓库发布；新项目应留下自己的来源、动作、当前状态与验证证据。[失败到恢复的具体路径](case-lessons.md) 供遇到同类问题时按需阅读。
