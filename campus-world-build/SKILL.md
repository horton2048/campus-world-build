# 校园世界策划与制作

帮助用户明确想让谁进入怎样的校园、体验什么，再依据约定自主制作和验收。既接“我要复刻学校”，也接“继续优化现有校园”。不预设怀旧、散步、竞速、社团或幻想题材。

## 先理解，再开工

恢复已有对话、工程、资料与检查点，不重问已明确的信息。先读 [需求打磨](references/office-hours.md)：每轮只追问一个会改变作品的关键缺口，顺着用户最明确的体验、地点、风格或用途深入；Agent主动查资料、贡献具体创意、复述玩家经历并展示示意图。清单用于内部核漏，不作为固定问卷。

对齐范围、核心体验、校园辨识特征、风格参考、真实与创作边界、设备/预算/期限及保留项。用户明确交付目标后即可制定方案，不为了凑轮次反复提问。技术细节由Agent决定并说明重要假设；用户决定审美、意义和需求取舍。

已有工程先原生只读盘点再讨论本次差量；记录“改什么、保留什么”，不重跑完整新建问卷。用户只要求讨论时不创建工程或保存方案；明确开工后记录轻量施工约定及可检验标准。

## 自主执行循环

确认目标后读 [施工与自主验收](references/autonomous-loop.md)。恢复现场→检查能力→选能独立验收的一轮→记录基线→按已选入口施工→核对真实结果→对照资料与正常试玩→不达标修正→通过后保存检查点，继续队列。最后整体串联验收、完全退出冷开和交付。

验收由Agent执行，不把每栋建筑或每次摆放检查交回用户。用户可以体验和反馈，但其确认不替代技术、外观与玩法证据。只在需求冲突、资料身份歧义或需要改变约定/费用授权时集中请用户取舍。能力未知先做小样；连续无改善时重新诊断，不无上限重生成或偷偷缩小需求。

## 原生操作与恢复

优先遵守用户明确指定的入口和禁止项。检查编辑器、账号与实际工具：MCP 和 CLI 可用时，优先 **Agent → MCP → CLI → 编辑器**，读 [原生执行](references/native-execution.md)；不可用而电脑操作工具可用且用户允许时，经编辑器界面操作，读 [电脑操作](references/computer-use.md)。用户禁止电脑操作时不得回退；两条路都不可用就报告缺口并继续资料工作。不得臆称所有动作已支持，也不通过终端直接执行CLI制作或手改工程。

正式工程先只读核对身份，使用当前入口支持的完整复制方式创建独立测试副本并验证；无法可靠复制或核实则暂停修改正式工程。不能将正式工程改名绕过写入保护。沿用已有费用授权；生成不等于免费，未知写入不重放。

用 `scripts/campus_checkpoint.py` 与真实操作回执持久续做，见 [检查点](references/checkpoint-tool.md)。外部操作前记录prepared意图/输入指纹，响应后保存真实任务/资产/实例句柄。未知/在途先查询原作业与现场，不换输出目录或清claim重提。

地图决定空间关系，已核实实景决定辨识特征；模型尺寸、正面、锚点与地面须实测。整栋建筑不套摆件尺寸限制。美化已有校园时，先冻结名称、位置/朝向、占地、入口、碰撞和脚本依赖，不能以更漂亮为由移动建筑或删玩法。

## 验收和交付

分列操作完成、原生持久化、视觉效果、正常玩法证据；HTTP成功、生成完成或截图存在均不足以宣称达标。Agent实际看图并对照已选参考，提出判断依据与缺口，不能编造还原百分比。测试方法与范围参考 [小例验收](references/acceptance-case.md)。

最终展示工程名称、实机对照、本次完成项、未完成/待修正项、已知限制与续做入口。地图/照片来源、逐项任务清单、参考版本和验收证据保持对应。资料或版本变化时重新检查受影响项，不重做无关已通过项。派生校园偏好时再读 [派生规则](references/customize-campus-skill.md)。
