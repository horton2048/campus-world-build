# 按官方地图持续复刻校园

用户可以只说“使用 $campus-world-build，复刻【学校】【校区】”。Agent 主动找到官方地图、盘点全图、逐栋检索并核实照片，使用造世界的可用生成与编辑能力，按清单连续完成复刻。已有目标、工程和资源边界从上下文沿用；资料可选提供，不必先备齐地图或每栋照片。

**默认顺序：全图清单 → 逐栋照片 → 统一布局与生成任务 → 技术校准 → 逐栋生成、落位、接地 → 全量复核 → 美化与玩法。**样板只验证制作方法，不把完整校园的目标缩成一栋楼和一段路。保留用户最新明确范围；若只要求局部，则不要扩建全校。

本 Skill 从真实多轮纠正中整理，目标是减少漏项、重复确认和用户催促；尚未证明任何校园都能一次提示达到相同效果。历史诉求与执行偏差见 [原始目标与工作流](references/intent-and-workflow.md)。整校长程任务同时读 [跨上下文施工循环](references/long-running.md)；按 [检查点工具](references/checkpoint-tool.md) 建立可恢复记录。

## 0. 一次接收任务，恢复已有工作

- 从现有会话、项目和资料中确认学校/校区、完整范围、保留区、当前阶段、可用编辑工程、成本与时间边界。已知信息直接沿用。只有校园身份冲突、必需资料不可访问、预算/权限或重要审美取舍需要用户决定时，集中问一次；不要逐栋索图或逐批请求“继续”。
- 先读短恢复卡和当前项详情，再查询真实工程、未保存修改、在途任务、资产与实例，避免重复新建。新任务用 `scripts/campus_checkpoint.py` 建立工作记录；[工作记录模板](assets/campus-ledger.template.json) 供字段/兼容参考，不是编辑器配置，也不是要整份灌入上下文的长聊天。没有脚本执行能力时采用长程协议中的等价分项文件方案。
- 自行定位当前官方指南与相关教程，读取模型生成、导入、保存和验收前提，复用已有笔记。发现当前工具并核对 schema、项目身份和实际连接；已有获权能力直接续用。新连接或安装按本次授权处理。详见 [工具路由](references/tool-routing.md) 与 [指南和 MCP](references/guide-and-mcp.md)。
- 在本轮可执行范围持续推进；登录/必要账号权限可集中提示，额度未知不按无限消费。不要自动恢复已暂停的定时任务，也不继承案例中的额度重置、购买、发布或删除授权。Skill 本身不唤醒已停止的宿主；停止前保存恢复入口，不能把可恢复写成仍在后台施工。

## 1. 先找官方地图，建立全图对象全集

优先学校官网、官方招生/校区页面，再用可靠辅助图交叉核对。记录来源、日期（未知则标未知）、校区边界、指北、地图版本和比例依据。排除图例、二维码、标题等非空间内容。

逐区列出建筑/建筑组、宿舍、教学与学院楼、校门、食堂、体育场与篮球场等场地、道路名称与走向、水体、绿地和公共设施。每项有稳定 ID、校园真实名称、地图位置与证据。未知建筑保留“待辨认”，不能凭颜色或轮廓猜用途；多个标签不必然是多栋独立楼。

把地图全集与当前场景逐项匹配，形成 **已达标 / 待修正 / 未做** 差异表。资产包数量、节点数、入口数都不能代替地图覆盖数量。第一批就建立清单，不等用户看到缺楼后再补。

## 2. Agent 逐栋找照片，先核身份再生成

按全图清单自动检索：学校官网 → 学院官网/官方新闻 → 其他可核实的公开实景。用户已有图片先利用；不要把检索责任转交给用户。

每栋建立主参考与补充图组，实际查看图像并记录来源、身份依据、时间与角度。核对同名建筑/不同校区、改造前后、正背面、楼翼、屋顶和入口；文章日期不自动等于拍摄日期。地图决定位置，照片决定外形，两者相互校验。

- 参考充分：进入该栋生成任务。
- 身份或角度不足：继续换来源/关键词找图，保留缺口；有其他可做项目时转下一项，不为一栋卡住全校。
- 仍无法解决的真实冲突：把已查来源、候选与所需决定集中向用户说明。普通照片不足不需要每次都打断用户。

没有照片的占位、估算外壳或局部立面可以保留为中间态，但不能标为“照片复刻达标”。

## 3. 先写全校园规格，再拆成逐栋任务

在批量生成前写清全校园分区、道路、建筑关系、地面与阶段顺序；升级校园生活时也先形成完整文字总设计，再按区域制作。

确定共同原点、方向、工作单位和位置转换。没有可靠比例尺时标“工作估算”，不称精密测绘；地图位置与模型导入缩放分别记录。每栋任务包括参考图组、整体体量、楼翼/屋顶/入口、需保留特征、已知和估算尺寸、朝向、落位锚点、预算及验收镜头。

第一阶段锁定建筑、道路、场地和接地覆盖；每栋在生成前仍必须取得可核实的照片依据，不能为凑覆盖数量生成无证据盒子并标达标。默认基础覆盖门槛是：地图全集无漏项，建筑有合理完整体量而非局部薄片，场地和路网存在，位置方向与地图相符，底部和入口合理接地。之后继续补足照片相似度与细节；基础覆盖通过不等于完整精细复刻完成。景观、主题装饰与玩法仅按用户目标进入后续阶段。用户调整阶段时保留全部未完成基础项，不能让局部活动掩盖地图缺项。

## 4. 小样只校准技术，验证后自动扩大批次

检查当前文件大小、面数/材质、场景容量与积分限制。用一件有代表性的模型走通生成/复用 → 入库 → 入场 → 尺寸/朝向/接地 → 保存 → 回读/看图，验证当前来源的导入规则。

选择整栋参考图生成，或可控主体加照片立面等受支持方法；按相似度和可修改性决定，不强求所有楼同一方式。不能只生成入口牌或正面薄片，却把整栋标完成。既有楼体保留、二创另做独立模块时，明确这是后期美化任务。

样板通过后按全图队列自动推进。除非用户要求审定，或出现影响全局的真实取舍，不把逐栋确认设为关卡。遇比例、镜像或地形前提问题时读 [实战教训](references/case-lessons.md)。

## 5. 按清单持续执行逐栋闭环

每一栋/每一区：**检索核资料 → 图组与任务 → 生成/搭建 → 对照照片 → 校尺寸位置 → 入库/落场 → 接地与通行检查 → 保存 → 更新清单 → 下一项。**

- 队列优先：未做/缺完整楼体与场地 → 位置或悬空 → 缺照片/外观不符 → 细部 → 后续玩法。用户明确插入紧急项后，再返回队列。
- 资料与代码可分工；同一场景由单一写入负责人顺序修改。生成期间可研究下一栋，不能并行覆盖同一实例。
- 外部写入前保存操作意图、输入快照和去重指纹；回包后立即保存真实句柄/结果，再核任务、资产和实例。任务已提交、产物生成、资产入库、场景实例、保存、看图与运行分别记录。
- `prepared/submitted/running/unknown` 的作业先查原句柄/产物与场景；观察超时或丢回包不等于失败。没有权威终止及副作用排查证据，不重发冲突操作。未知写入优先核实，期间可查其他楼照片。
- 每个对象的方法、错误签名、尝试次数与依赖持久保存，同法同输入两次失败没有新证据就换路或转下一项，不能因换会话清零。不得靠反复测已通过的路线代替全图推进；相关修改、新失败或明确缺口才扩大回归。
- 每次写入前后、每栋/批结束及交接前更新检查点，短卡只列索引和下一动作；逐栋详情按需读，长日志分页取证。不要依赖宿主必定暴露剩余上下文百分比。
- 中断恢复按“任务约定 → 未终作业 → 真实工程/保存读回 → 当前对象详情 → 全图下一可做项”续接。全部依赖受阻就保存并集中报告，不空转，也不标全校园完成。完整状态与循环规则见 [长程协议](references/long-running.md)。

## 6. 每栋和全图分别验收，报告真实完成度

| 检查层 | 要回答的问题 |
|---|---|
| 地图覆盖 | 全图列过的建筑、道路和场地是否都有对应项，位置与方向是否相符？ |
| 照片身份与相似度 | 参考是否确属该楼，该模型哪些部分受照片支持，哪些仍是估算？ |
| 整栋形态 | 是占位/局部，还是有合理体量、楼翼、屋顶与入口的整栋？ |
| 接地与通行 | 全周墙脚、柱脚、台阶、坡道是否合理接地，入口及必要路线能否连续走通？ |
| 保存与可恢复 | 当前实例是否存在、原生保存和回读是否成功，文件与场景版本是否对应？ |
| 运行体验 | 该阶段需要的交互、重复触发与退出是否实测；手机/多人/性能未测则留待验。 |

保留 **未生成 → 已生成 → 已入库 → 已落场 → 已保存 → 视觉已核 → 运行已核** 状态，同时单独记录占位/局部/整栋和质量是否达标。一张正面图、入口能走或射线命中，不能替代整栋/全校验收。纯静态部件无需某项玩法测试时写“不适用”及原因。

每批按 **用户目标 → 实际动作 → 图片/文件/场景证据 → 缺口与下一项** 记录。优先汇报全图覆盖变化和未完成项，不能只展示成功局部。规则已读、实际动作已做、结果已验三者分开；模板中的 `ruleChecks` 用于对应。

最终重新审计地图全集、逐项质量证据、未知任务与原生保存回读。队列空、会话结束或预算耗尽不能当完成；清单漏了一片区域时，即使现有项全“完成”也不能通过。检查点工具只能检验记录一致性，照片、场景与实走仍须实际核验。

## 7. 基础复刻后，再扩展风格和生活

基础全量与接地门槛通过后，继续完成约定的照片相似度与精细复刻。美化、校园生活和玩法只在用户要求时追加；若只要复刻，达标后不顺带扩展。进入这些后续阶段时优先查官方资产与交互模板。生成、碰撞、UI 与重复使用分开验；装饰好看不等于玩法成立。

每批保存场景、截图、来源、模型/实例映射、缺口、下一步和预算余量。全图未达约定标准时继续在授权范围内推进，真实受阻则交代已查结果与可恢复状态。作品上传/公开发布与制作中的模型导入存储是不同动作；按用户对各动作的当前授权执行，发布后核验远端状态。若用户明确禁止所有云端上传而所需导入会上传模型，先集中澄清一次；不要把“不发布世界”误读成禁止已获准的日常导入。

## 只读 GLB 检查

`python3 scripts/inspect_glb.py /绝对路径/模型.glb [--sha256 已知SHA256] [--max-mib 本轮实际上限]`

只用 Python 标准库，输出 JSON，返回码 0 表示容器、大小与稳定读取等离线检查通过，1 表示失败；它不生成、不导入、不证明世界尺寸、文字、碰撞或原生保存正确。
