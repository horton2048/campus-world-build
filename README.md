# 校园复刻全自动造世界 Skill

**把学校和校区告诉 Agent，让它帮你把熟悉的校园做成可以探索的造世界作品。**

你在 Agent 里提出想法、查看结果、反馈修改。Agent 负责查官方地图、逐栋找真实照片、制作建筑、摆放道路和场地、检查接地、保存并接着做。你不用学习建模、写代码或手工在编辑器里搭校园。

如果这份 Skill 对你有帮助，欢迎点击右上角 **Star** 收藏。下载与使用不以 Star 为前提。

## 什么时候适合用

- 参加造世界比赛，想以自己的学校为创作起点。
- 已有校园工程，希望沿完整地图补楼、修位置、改外观。
- 想在校园基础上做迎新路线、毕业回忆、社团任务或其他创意。

目标是有地图依据、建筑特征能认出来、主要路线可通行的室外校园；之后再加自己的风格和玩法。它不是精密测绘工具，也不承诺自动还原每个房间。

## 最快开始：先把这句话交给 Agent

使用能读取文件、联网并操作电脑或编辑工具的 Agent。只有文字聊天能力，暂时只能完成研究和方案，不能直接建出场景。

> 请读取 https://github.com/horton2048/campus-world-build 中的 Skill，帮我加载并用于复刻【学校全名】【校区全名】。我希望全程在 Agent 中完成创作。请先检查准备条件，能自行完成的直接做；需要我本人登录、申请权限或决定额度的，集中告诉我。

把方括号替换为自己的学校和校区。若 Agent 不能读取仓库，点 **Code → Download ZIP**，解压后把其中含 `SKILL.md` 的整个 `campus-world-build` 文件夹交给它；保留 `references`、`assets` 和 `scripts`。安装位置由所用 Agent 决定，不需要你猜目录。

加载完成后，日常启动只需：

> 使用 `$campus-world-build`，复刻【学校全名】【校区全名】。

你只需确认学校校区、想法和资源上限，完成必须本人处理的登录或创作权限申请。已有账号、工程和偏好直接沿用。地图、逐栋照片、操作手册与工具检查由 Agent 负责；手头已有资料可以补充，不必先准备全校图库。

## 用的时候，你会看到什么

| 阶段 | Agent 给你看 | 你要做的事 |
|---|---|---|
| 开工 | 正确校区、制作范围、准备状态和待办 | 核对校区；处理必要的本人验证和资源决定 |
| 第一批作品 | 首批建筑与场地的实际画面，以及待修正项 | 用日常语言指出不像的地方或想保留的特征 |
| 持续复刻 | 全校园哪些已达标、哪些未做、下一步做什么 | 有想法就反馈，不必逐栋催“继续” |
| 校园基础完成后 | 完整范围的核对结果、可走路线和保存结果 | 判断校园气质，再决定是否增加风格与玩法 |

比如直接说：“图书馆正门不像，请找正面照片再修”“保留教学楼外形，把操场做成毕业留言空间”。中断后，在同一个项目里说“继续复刻我的校园”，Agent 应先恢复进度再接着做。

## 需要留多少时间

下面是**安排首次尝试的建议，不是实测完成时长或速度保证**：

| 事情 | 建议怎样安排 |
|---|---|
| 你说明目标、确认准备 | 先留 10–20 分钟；第一次账号申请、登录验证和连接配置另计 |
| Agent 第一轮试跑 | 先安排半天可运行窗口，用来核资料、校准方法并争取看到首批作品；进展取决于工具是否已接通 |
| 完整校园与精修 | 按多天迭代安排，不能把第一批建筑等同整校完成；校准后由 Agent 按实际楼数、生成等待和返工情况更新预估 |
| 你看结果、提反馈 | 每次先留 5–10 分钟，集中说清最想改的地方；不必全程盯着 |

Agent 会区分你的投入、机器执行时间和平台等待。没有本项目实际数据时，它应先说明未知项；不能凭这份 Skill 承诺“几分钟完成整校”。北工大案例经过多轮、跨日迭代，尚无采用当前 Skill 复刻新校园的完整速度基准。

## 从通用 Skill 变成你的校园专属 Skill

先用通用流程跑通你的校园，再把稳定的偏好固化下来。例如：

> 在这份 Skill 基础上，为我的校园建立一份项目专属 Skill。保留地图复刻、逐栋照片和检查流程，把我已确认的建筑风格、必留地标与反馈整理进去。先给我看改动，再按我的确认保存，以后都照这个版本做。

你用自然语言讲需求，Agent 负责整理和保存。一次修改作品不自动变成永久规则；试验中还没证实的方法也不会包装成成功经验。专属版本留在你的项目里，不覆盖通用 Skill，也不自动公开你的照片、工程或聊天。

## Agent 工作台需要什么

“全程在 Agent 中创作”指你不用手工建场景。Agent 仍会调用造世界工具，或自动操作后台编辑器；编辑器可能需要保持运行。账号、创作权限和可用额度必须真实存在，Skill 不会凭空提供这些资源。

Agent 应先读[开工与时间预估](campus-world-build/references/agent-workbench.md)，自行检查官方指南、当前能力和目标工程。官方入口、社区工具来源和实际分工均在 [Skill 的工具说明](campus-world-build/references/guide-and-mcp.md) 与[工具路由](campus-world-build/references/tool-routing.md)中，不需要新手先读完再开始。没有可靠的生成或编辑能力时，它会明确报告卡点，先做能完成的准备，不把清单说成作品。

## 给 Agent 与进阶使用者

- [Skill 主流程](campus-world-build/SKILL.md)：地图 → 照片 → 制作 → 验收 → 续做。
- [完整启动任务](campus-world-build/assets/start-prompt.md)：需要指定已有工程、保留区或资源边界时使用。
- [原始诉求与工作流](campus-world-build/references/intent-and-workflow.md)、[实际失败经验](campus-world-build/references/case-lessons.md)：规则来自哪里，以及哪些结果尚未验证。
- [长程执行](campus-world-build/references/long-running.md)、[检查点工具](campus-world-build/references/checkpoint-tool.md)：恢复进度、核查未知任务与避免重复生成。

## 验证与许可

目前依据真实北工大制作过程沉淀；检查点工具 18 项离线回归已通过，独立 Agent 在合成工程中验证过启动、恢复与补漏。这些验证不等于新校园已全程自动生成，也不替代真实画面、接地、手机或多人运行验收。

本地记录机制可用 `python3 -B -m unittest discover -s tests -v` 验证，不调用编辑器、不消耗生成额度。自带脚本使用 Python 标准库；`inspect_glb.py` 仅检查模型容器，`campus_checkpoint.py` 仅管理记录，两者都不是生成服务。
